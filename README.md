# يلا رياضة | YALLA RIYADA

**المنصة الأقوى في الوطن العربي** — The Strongest Sports Platform in the Arab World

منصة رياضية متعددة الألعاب: مباريات ونتائج، أخبار، مساعد ذكي (Yalla AI)، متجر، مفضلة وإشعارات، بالعربية والإنجليزية.
المشروع: React + Vite + TypeScript + React Router، مع خادم وسيط صغير (Node بدون حزم) للمفاتيح السرية.

> ## ⚠️ حالة المشروع بصراحة
> - **الواجهة تعمل ببيانات تجريبية موسومة بوضوح** («تجريبي»): المباريات والأخبار والمنتجات والأسعار والفرق واللاعبون كلها خيالية.
> - **لم يُربط مزود بيانات رياضية حقيقي**، ولا مصدر أخبار، ولا بائعون حقيقيون.
> - **الحسابات تجريبية محلية** (تُحفظ في المتصفح فقط وبلا تحقق من كلمة المرور).
> - **المساعد الذكي**: التكامل مكتوب ومُختبَر بمزود وهمي محلي، لكن **لم يُجرَّب مع مزود حقيقي** لأنه يحتاج مفتاحك.
> - **لا يوجد دفع إلكتروني** إطلاقًا.
> - **لم أستطع تشغيل `npm install` ولا `npm run build` أثناء الكتابة** (بيئة الإنشاء تمنع الوصول لسجل npm). شغّلهما على جهازك أول شيء — انظر «الاختبار».

## التشغيل على Windows (خطوة بخطوة)

1. ثبّت **Node.js LTS** (الإصدار 18.18 أو أحدث) من <https://nodejs.org> ثم أعد فتح الطرفية.
   للتأكد: `node -v` و `npm -v`.
2. فك ضغط المشروع، وافتح **PowerShell** داخل مجلد `yalla-riyada` (Shift + كليك يمين ← «Open in Terminal»).
3. ثبّت الحزم:
   ```powershell
   npm install
   ```
4. انسخ ملف البيئة (اختياري في أول تشغيل):
   ```powershell
   copy .env.example .env
   ```
5. شغّل الواجهة فقط:
   ```powershell
   npm run dev
   ```
   ثم افتح العنوان الذي يظهر (عادةً <http://localhost:5173>).
6. لتشغيل الواجهة **والخادم الوسيط** معًا (للمساعد الذكي وصفحة اتصل بنا):
   ```powershell
   npm run dev:all
   ```
   الخادم على المنفذ 8787 وVite يحوّل `/api` إليه تلقائيًا.

## الصفحات المنفّذة (كل واحدة Route مستقل)

`/` الرئيسية · `/matches` · `/matches/:id` · `/news` · `/news/:id` · `/sports/:sport` · `/teams/:id` · `/players/:id` · `/assistant` · `/store` · `/store/:id` · `/favorites` · `/notifications` · `/profile` · `/login` · `/register` · `/settings` · `/about` · `/contact` · `/privacy` · `/terms` · و404.

المسارات تستخدم **HashRouter** (`/#/matches`)، فتعمل على أي استضافة ثابتة (GitHub Pages) والتحديث والروابط المباشرة وزر الرجوع/التقدم سليمة دون إعدادات إعادة توجيه. لمسارات نظيفة (بدون `#`) بدّل إلى `BrowserRouter` في `src/main.tsx` وأضف قاعدة إعادة توجيه إلى `index.html` في الاستضافة.

## الهوية البصرية

`public/assets/brand/`: `logo-mark.svg` (الرمز) · `logo-horizontal-dark.svg` / `logo-horizontal-light.svg` · `logo-square.svg` · `favicon.svg` · `og-image.svg` + نسخ PNG (`icon-192`، `apple-touch-icon`، `logo-*.png`، `og-image.png`).
الرمز أصلي: حرف Y كسهم اندفاع مع كرة وخطوط سرعة. اللوجو مستخدم فعليًا في الهيدر والفوتر والأيقونة وصفحة المساعد.
**ملاحظة:** نص «يلا رياضة» داخل ملفات SVG الأفقية يعتمد على خط Cairo؛ حوّله إلى Outlines (Inkscape/Illustrator) قبل الطباعة أو تسليمه لمصمم. نسخ PNG الحالية رُسمت بخط متاح في بيئة الإنشاء.

**لا توجد صور فوتوغرافية** في هذه النسخة: استُبدلت برسوم SVG مولّدة (`SportArt`) كي لا نستخدم صورًا بلا ترخيص. لإضافة صور حقيقية استخدم مصادر مرخّصة (Unsplash/Pexels مع مراجعة الشروط، أو صورك).

## منع الزوم (وحدوده)

ما نفّذناه: `maximum-scale=1` في وسم viewport، و`touch-action: manipulation` (يمنع زوم النقر المزدوج)، وحقول الإدخال 16px (يمنع زوم iOS عند التركيز). **لا نستخدم JavaScript** لحجب اللمسات، فيبقى التمرير ولوحة المفاتيح وقارئات الشاشة سليمة.
**حدود:** iOS Safari وبعض المتصفحات يتجاهلون `maximum-scale` عمدًا، وإعدادات إمكانية الوصول (تكبير الشاشة/الخط) تتجاوز المنع — وهذا مقصود في هذه الأنظمة. تنبيه: منع التكبير يضر بضعاف البصر؛ فكّر في إزالة `maximum-scale=1` من `index.html` إذا كان الوصول أولوية.

## تفعيل المساعد الذكي (Yalla AI) فعليًا

الواجهة لا تحمل أي مفتاح. تتصل بـ `/api/chat` في `server/index.js` وهو الذي يكلّم المزود.

1. أنشئ مفتاح API من مزود (مثلًا Anthropic من <https://console.anthropic.com>). **التكلفة:** الاستخدام مدفوع حسب الرموز (tokens)؛ راجع صفحة الأسعار الحالية وضع حدًّا للإنفاق من لوحة المزود قبل الإطلاق.
2. في `.env`:
   ```
   AI_PROVIDER=anthropic
   AI_API_KEY=مفتاحك_هنا
   AI_MODEL=claude-sonnet-5-5
   ```
   (لأي خدمة متوافقة مع OpenAI: `AI_PROVIDER=openai` و`AI_BASE_URL` و`AI_MODEL` المناسب.)
3. أعد تشغيل الخادم: `npm run dev:all`.
4. افتح `/#/assistant`: الشريط العلوي يصبح «الذكاء الاصطناعي متصل». **قبل ذلك** يعرض بوضوح «وضع تجريبي» والردود ليست من نموذج حقيقي.

الخادم يحدّد الطلبات (20/دقيقة لكل IP)، يقصّ الرسائل، ولا يمرّر تفاصيل أخطاء المزود للمتصفح. للإنتاج استخدم حدًّا مركزيًا (Redis أو بوابة API) وراقب التكلفة.
**استضافة الخادم:** GitHub Pages ثابتة ولا تشغّل `server/`. انشر الخادم على خدمة مثل Render/Railway/Fly.io (أو حوّله إلى Serverless Function) واضبط `VITE_API_BASE_URL` على عنوانه و`ALLOWED_ORIGIN` على عنوان موقعك.

## ربط بيانات المباريات الحقيقية

1. اختر مزودًا (مثل API-Football أو Sportmonks أو TheSportsDB). **راجع الأسعار وحدود الطلبات وحقوق عرض الشعارات والبيانات قبل الاعتماد عليه** — الخطط المجانية غالبًا محدودة جدًا للمباشر.
2. ضع `SPORTS_API_BASE_URL` و`SPORTS_API_KEY` في `.env` (على الخادم فقط).
3. اكتب المحوّل في `server/providers/sports.js` (الأشكال المطلوبة موثّقة في أعلى الملف وتطابق `src/types.ts`)، وأضف تخزينًا مؤقتًا (cache) لتوفير الحصة.
4. فعّل `VITE_SPORTS_DATA_MODE=live` في `.env.local`.

حاليًا الخادم يردّ `501` صراحةً بدل اختلاق بيانات. ملاحظة: في وضع `live` تُجلب المباريات والتفاصيل والفرق واللاعبون من الخادم، أما الأخبار والفرق المميزة وقوائم الفلاتر فما زالت من بيانات المشروع التجريبية حتى تُنفَّذ لها نقاط API مماثلة.

## الأخبار والمتجر

- **الأخبار:** نصوص أصلية كتبها المشروع (شروحات قوانين وتقارير مباريات خيالية). للأخبار الحقيقية اربط مصدرًا مرخّصًا (RSS/API باتفاقية) أو لوحة إدارة (CMS)؛ الطبقة في `src/services/newsApi.ts`.
- **المتجر:** منتجات تجريبية بلا روابط شراء. للبائعين الحقيقيين ضع `buyUrl` الفعلي في `src/data/products.ts` (أو من قاعدة بيانات)؛ وسم العمولة يُلحق تلقائيًا من `Vendor.affiliateTag` (`outboundUrl` في `storeApi.ts`). تأكد من شروط برامج العمولة وإفصاحاتها القانونية في بلدك.

## الحسابات والمفضلة والإشعارات

- **المفضلة والتذكيرات وسجل المحادثات** محفوظة محليًا (`localStorage`) على الجهاز.
- **الحساب التجريبي** (`src/services/authService.ts`): واجهة `AuthProvider` جاهزة؛ اكتب تنفيذًا آخر (مثلًا **Supabase Auth**) وبدّل `authProvider` — لا حاجة لتغيير أي صفحة. Supabase له خطة مجانية بحدود (عدد المستخدمين، التخزين، إيقاف المشاريع الخاملة)؛ راجع صفحة الأسعار الحالية قبل الاعتماد عليه. للمزامنة بين الأجهزة تحتاج جداول للمفضلة والتفضيلات في قاعدة البيانات.
- **تذكير المباراة** يعمل ما دام الموقع **مفتوحًا** في المتصفح (فحص كل 20 ثانية) مع إشعار المتصفح بعد منح الإذن. الإشعارات والموقع مغلق تتطلب **Web Push** (Service Worker + مفاتيح VAPID + خادم يرسل). تنبيهات «الأخبار المهمة» غير مفعّلة لنفس السبب وموسومة بذلك في الواجهة.
- **اتصل بنا:** يُرسل إلى `/api/contact` ويُحفظ في `server/data/contacts.jsonl`. إن لم يوجد خادم تظهر رسالة خطأ صريحة ولا تظهر «تم الإرسال» كذبًا.

## اللغة والاتجاه

قاموسان كاملان في `src/i18n/` (العربية والإنجليزية)، تبديل من الهيدر أو الإعدادات، يُحفظ الاختيار، ويتغير `dir` و`lang` تلقائيًا. الأيقونات الاتجاهية تنعكس في RTL. أسماء العلامات التجارية تُترك كما هي. أسماء الفرق الخيالية لها ترجمة لأنها بيانات تجريبية (الأسماء الحقيقية تُترك بصيغتها الأصلية عند الربط).
مفاتيح الترجمة يفحصها `npm run check:i18n`.

## نحو تطبيق Android لاحقًا

الفصل بين الواجهة وطبقة `src/services` والخادم يسمح بإعادة استخدام نفس الـ API. خياران: تغليف الموقع بـ **Capacitor** (أسرع)، أو بناء تطبيق **React Native** يستهلك نفس نقاط `/api`. أضف Web App Manifest وService Worker لتحويل الموقع إلى PWA كخطوة وسيطة.

## الأمان

- لا أسرار في كود الواجهة: متغيرات `VITE_*` عامة ولا تحمل مفاتيح. المفاتيح في `.env` للخادم فقط، و`.env` مُستثنى في `.gitignore`.
- لا ترفع `.env` ولا `server/data/` إلى GitHub.
- نصوص الخصوصية والشروط **مسودات عامة** وليست استشارة قانونية — راجعها مع مختص قبل الإطلاق.
